# 006受理时延验收记录

日期：2026-10-29。本地Docker Compose，单Java worker、MySQL、Next生产构建，未配置网络限速。前端代码提交9934a67；无真实AI。样本不含cookie/token。

## 测量口径

- API：容器内Node通过Next同源代理调用Java/MySQL；身份、模板预热及PNG上传在计时前完成。performance.now从POST前到202响应JSON及新ID解析完成。10次串行，每次等后台成功后再提交下一项。测量起始时间为工具记录2026-10-29T09:24:55.020Z。
- 浏览器：内置浏览器http://localhost:3000，真实文件选择、上传、点击提交。每次上传完成后计时，从驱动点击提交前到新编号对应DOM可见并读取唯一编号；包含驱动与DOM读取开销，是页面显示编号耗时的保守上界，不是浏览器Performance埋点或API耗时。已有编号不算新样本。
- 两组均省略simulation，默认三个阶段各2000ms。API逐项核对六事件、每阶段至少2000ms、后台成功总耗时至少6000ms。浏览器可连续提交，存在少量排队，10项最终全部成功；不将制作和排队时间算入受理耗时。
- 时间阈值严格为每项<2000ms。工具连接/审批等待发生在计时区间之外；没有剔除任何已计时样本。页面显示的服务端创建时间与工具时钟存在偏差，因此不混用两者计算时延，全部耗时使用各自单调时钟。
