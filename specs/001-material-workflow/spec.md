# Feature Specification: 素材制作与异步任务闭环

**Feature Branch**: `001-material-workflow`

**Created**: 2026-10-29

**Status**: Archived project baseline（由002～005实施；复查仍有待修及未验证项）

**Input**: 用户要求根据 README 开始项目，本轮完成前置工作，使用 SDD + TDD 和 speckit skills，独立目录与仓库，及时提交，全程不使用子智能体。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览模板与素材要求 (Priority: P1)

作为访客，我可以按分类浏览模板并进入详情，了解需要哪些图片。

**Why this priority**: 制作前先能选到适合的模板；可独立交付模板浏览切片。

**Independent Test**: 使用示例模板，切换两类分类，打开要求不同图片数量的详情。

**Acceptance Scenarios**:

1. **Given** 至少两类、三张模板，**When** 浏览及切换分类，**Then** 展示正确卡片、标题、封面与筛选结果。
2. **Given** 某模板需要两张图片，**When** 进入详情，**Then** 显示描述、示例、数量、允许类型及大小上限。
3. **Given** 列表为空、加载失败或模板不存在，**When** 浏览，**Then** 分别出现空态、可重试错误或不存在提示。

### User Story 2 - 上传素材并受理制作 (Priority: P1)

作为用户，我可以预览、替换或移除图片，准备好后提交，立即获得可以跟踪的任务。

**Why this priority**: 从浏览进入制作的必要入口。

**Independent Test**: 使用预置模板和当前身份上传素材，提交后在制作完成前取得任务编号。

**Acceptance Scenarios**:

1. **Given** 素材槽位，**When** 选择合法图片，**Then** 显示上传反馈和预览，替换/移除后仅保留当前素材。
2. **Given** 数量不足、类型/大小不符、上传失败或上传未完成，**When** 尝试提交，**Then** 明确说明原因且不受理任务；绕过页面也必须拒绝无效素材。
3. **Given** 已准备好图片，**When** 连续点击提交，**Then** 请求期间只发送一次；受理后展示等待状态，允许创建另一任务。
4. **Given** 素材属于另一用户或已经失效，**When** 提交，**Then** 拒绝且不创建任务。

### User Story 3 - 观察后台阶段及可控失败 (Priority: P1)

作为用户，我可以关闭页面后仍获得制作结果；作为演示者，我能重复观察指定阶段失败。

**Why this priority**: 原题核心是后台独立执行的多步骤业务。

**Independent Test**: 以预置任务分别验证成功和每个阶段失败，无需依赖上传界面。

**Acceptance Scenarios**:

1. **Given** 已受理任务，**When** 后台处理，**Then** 依次经历素材检查、模拟生成、结果整理，成功后可预览结果。
2. **Given** 任一指定失败阶段，**When** 执行到该阶段，**Then** 保存失败阶段和原因并停止后续步骤，每次重复均一致。
3. **Given** 处理尚未完成，**When** 关闭页面且不查询，**Then** 后台仍继续；反复查询不会推进、重启或回退任务。
4. **Given** 调长阶段耗时并创建多个任务，**When** 观察，**Then** 能区分等待、处理中、成功与失败。

### User Story 4 - 恢复个人历史与隔离多任务 (Priority: P1)

作为用户，我可以刷新恢复个人历史，同时跟踪多个制作任务，查询异常后继续查看。

**Why this priority**: 防止异步状态串扰和刷新丢失记录。

**Independent Test**: 以两个身份及各自预置历史，模拟乱序响应、请求失败、刷新和页面离开。

**Acceptance Scenarios**:

1. **Given** 多个不同阶段任务，**When** 收到各自更新，**Then** 时间、状态、阶段、错误、结果均归于正确任务。
2. **Given** 查询暂时不可用，**When** 请求失败，**Then** 保留已有任务状态，展示查询异常并允许恢复查询，不显示为制作失败。
3. **Given** 存在未结束任务，**When** 刷新，**Then** 恢复个人记录并继续自动跟踪；单个任务结束后停止跟踪它，全部结束后停止轮询。
4. **Given** 查询正在进行，**When** 离开页面或切换用户，**Then** 取消跟踪并忽略旧响应，不覆盖新用户或其他任务；不得读取他人素材、任务和结果。
5. **Given** 从未创建任务，**When** 查看历史，**Then** 显示可理解的空态和模板入口。

### Edge Cases

- 伪造图片类型、超限文件、重复素材 ID、不存在的素材、替换时旧上传迟到均须处理。
- 素材在受理后不可读，须在素材检查阶段失败并阻止后续执行。
- 提交成功但响应丢失时结果不确定，提示查历史，禁止自动重提；受理幂等不在本期范围。
- 队列满或入队异常不得产生永久等待任务；必须记录失败或拒绝受理，返回结果与记录一致。
- 已终结任务的延迟响应不得让界面回退；结果文件读取失败显示资源错误，不改写执行状态。
- 服务重启后不要求续跑；原未结束任务须给出可理解的中断说明。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供至少两类三张模板，支持分类、卡片和详情，包含不同素材数量要求。（R-02）
- **FR-002**: 系统必须允许选择、预览、替换和移除图片，表达上传中/失败；浏览器和服务端均校验数量、类型和大小，素材须可被后台读取。（R-03）
- **FR-003**: 系统必须校验模板、素材存在性和归属，受理后立即返回可跟踪编号，不等待制作完成；受理期间避免重复点击。（R-03/04）
- **FR-004**: 系统必须独立顺序执行三个阶段，保存阶段边界、状态、结果/失败原因；关闭页面或停止查询不影响执行，查询不推进执行，终态不可回退。（R-04/05）
- **FR-005**: 系统必须支持可重复指定任一阶段失败、调整耗时，失败后停止后续阶段。（R-06）
- **FR-006**: 页面必须分别表达上传、提交、等待、处理、成功、失败和查询异常；查询异常不等于执行失败且可恢复。（R-07）
- **FR-007**: 系统必须允许连续创建多个任务，按任务分别更新；清理终态任务、页面离开与用户切换后的跟踪并拒绝旧响应覆盖。（R-08）
- **FR-008**: 系统必须持久保存个人历史、创建时间、阶段、结果或失败原因，刷新可恢复并跟踪未完成任务。（R-09）
- **FR-009**: 系统必须提供可演示的用户身份策略；个人记录、素材和结果只能由所属身份读取/使用。（R-10）
- **FR-010**: 页面必须清晰表达加载、空态、错误；桌面和窄屏均可操作，控件有语义、键盘焦点及上传/图标标签。（R-03/11）
- **FR-011**: 交付必须包含可执行的关键行为测试、自动检查、完整源码和依赖版本、初始化数据、示例素材及运行说明。（R-01/12/13）
- **FR-012**: 交付必须说明配置、连接、接口、状态、模拟演示、身份、部署回滚、完成程度、投入、AI 工作流与复用来源，并优先提供隔离的一键运行入口。（R-13/14）

### Key Entities

- **用户身份**：个人记录的归属边界，可在同一浏览器刷新后继续使用。
- **模板/分类**：标题、示例图、分类、描述和素材约束。
- **素材**：所属用户、实际存储的图片、类型和大小。
- **制作任务**：所属用户、模板、素材、创建时间、整体状态、当前阶段、结果与失败原因。
- **阶段记录**：某阶段的开始、完成或失败，支持观察顺序和失败中断。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 可在两个分类中浏览三张模板，并正确展示至少两种不同素材数量要求。
- **SC-002**: 演示设定总制作耗时至少 6 秒时，本地正常负载下 10 次受理均在 2 秒内显示任务编号，之后可继续操作。
- **SC-003**: 成功场景按顺序出现全部三阶段；三个指定失败场景均只执行至失败阶段，终态后重复查看 10 次不回退。
- **SC-004**: 同时跟踪三个任务、包含成功/失败/处理中时，所有状态均不串扰；注入一次查询异常后仍能恢复原任务。
- **SC-005**: 刷新后恢复全部本人记录；切换身份后看不到原身份记录且旧请求不能覆盖新视图。
- **SC-006**: 所有任务结束或离开页面后，观察两个原查询周期不再发起自动状态查询。
- **SC-007**: 按交付说明在干净隔离环境完成启动、关键测试及成功/指定失败/多任务/刷新恢复演示，逐项记录验证结果。

## Assumptions

- 001保留总体需求与原量化目标；实施状态由002～005、验收对照和复查记录共同说明，不把旧计划迁移视为逐项验收通过。
- 无参考截图，列表、制作与历史三个页面自行设计；小屏验收基准宽度为 375px。
- 匿名身份满足演示，不扩展为账号注册、密码或第三方登录，不承诺清除浏览器数据后的身份找回。
- 不实现真实 AI、支付、模板管理、自动重试、幂等、断点续跑或集群；不使用随机失败。
- 自制本地图片，无付费或内部资源；运行与验收依赖容器环境，业务检查必须在容器中执行。
