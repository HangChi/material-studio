# Feature Specification: 模板浏览与详情

**Feature Branch**: `002-template-catalog`

**Created**: 2026-10-29

**Status**: Ready for planning（未实现）

**Input**: 按项目迭代图从001总体基线拆分，独立完成SDD与TDD周期；不使用子智能体。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按分类发现模板 (Priority: P1)

用户可浏览模板卡片，切换分类找到需要的素材样式。

**Why this priority**: 本feature的主要用户价值。

**Independent Test**: 两分类三模板；筛选不串入其他分类；未知分类显示空态。

**Acceptance Scenarios**:

1. **Given** 有效数据与前置条件，**When** 完成本故事的操作，**Then** 两分类三模板；筛选不串入其他分类；未知分类显示空态。
2. **Given** 无效输入或临时请求异常，**When** 尝试操作，**Then** 显示明确反馈且不污染其他对象的状态。

### User Story 2 - 查看要求与恢复浏览错误 (Priority: P2)

用户可打开详情，了解图片数量、类型与大小要求，遇到请求失败后能重试。

**Why this priority**: 补齐该切片可独立使用的可靠性。

**Independent Test**: 逐一验证1/2/3张要求；不存在模板提示；失败重试成功；375px和键盘可用。

**Acceptance Scenarios**:

1. **Given** 有效数据与前置条件，**When** 完成本故事的操作，**Then** 逐一验证1/2/3张要求；不存在模板提示；失败重试成功；375px和键盘可用。
2. **Given** 无效输入或临时请求异常，**When** 尝试操作，**Then** 显示明确反馈且不污染其他对象的状态。

### Edge Cases

- 不存在资源、空数据、请求失败、重复操作和迟到响应均须可验证。
- 后续feature未实现的能力不展示为可用入口；不以占位数据声称完整闭环。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须展示至少两类、三张带标题/封面的模板，数据来自服务端，分类筛选正确。
- **FR-002**: 系统必须详情展示标题、描述、示例、图片数量/类型/大小；每张模板可直接访问。
- **FR-003**: 系统必须加载、空结果、网络错误和不存在模板分别提供明确反馈；请求异常可重试。
- **FR-004**: 系统必须快速切换分类时旧响应不得覆盖新分类；卸载后清理请求。
- **FR-005**: 系统必须375px无横向溢出，分类/卡片/重试控件可键盘访问且有可见焦点。
- **FR-006**: 系统必须提供本切片的容器启动、测试/构建、初始化数据、示例素材与自动检查说明。

### Key Entities

- **分类**：标识与名称。
- **模板**：标题、描述、分类、封面、图片约束。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少两个分类和三张模板可浏览，全部封面可读取。
- **SC-002**: 三个详情精确显示1/2/3张图片要求、两种允许类型及5MiB上限。
- **SC-003**: 加载/空/失败/不存在四种场景均能单独验证；快速切换不会显示过时结果。
- **SC-004**: 按隔离环境说明通过本切片测试与构建，375px可完成分类和详情浏览。

## Assumptions

- 匿名可读；本期不做身份、上传、任务受理/执行、历史。模板不提供管理CRUD。无需UI参考图；使用自制本地图片。
- TDD必须记录真实RED/GREEN；计划中的测试不代表已运行。
