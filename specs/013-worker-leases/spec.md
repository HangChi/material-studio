# Feature Specification: 多实例安全领取
**Created**: 2026-10-30
**Status**: Complete
**Input**: 第10项第二独立增量；在012断点基础上支持多个执行实例共享任务。
## User Scenarios & Testing
### US1 唯一领取（P1）
两个实例同时看到同一待办，仅一个可以开始执行；另一个继续处理其他任务。存活任务不被新实例启动过程重置。
验收：并发领取同任务一次成功；两个真实实例均能处理任务、无重复阶段/版本冲突；仍保留有界本机队列和三次执行预算。
### US2 过期接管与旧线程隔离（P1）
实例崩溃后租约到期，由其他实例从有效断点接管。旧实例即使恢复，也不能提交阶段、重试、失败或覆盖新结果。
验收：租约未到期不接管，过期只允许一次新代次；旧代次完成/失败/重试全拒绝；新结果字节保留；取消保持终态。
### Edge Cases
数据库短暂不可用不得延长已失效租约，失去租约的线程可能仍计算但不能发布。文件卷须所有实例共享；不宣称执行恰好一次，保证只有当前代次可提交。
## Requirements
- FR-001 每次领取获得唯一实例和递增执行代次；有效租约内仅当前实例可更新制作状态，时间判断以权威存储为准。
- FR-002 活动任务周期续租；过期租约不可复活；进程退出释放自身租约，不能释放后继代次。
- FR-003 启动恢复只处理已过期或旧版无租约活动任务，不动其他实例有效租约。
- FR-004 每个阶段开始/完成、断点登记、失败/重新排队都校验执行代次；独立产物名避免旧执行覆盖胜者文件。
- FR-005 保留012断点、配额、取消、三次预算、现有API；新代次拒绝时不发布或清理胜者结果。
## Key Entities
任务租约：任务、实例、执行代次、有效期；运行上下文：当前线程拥有的代次。
## Success Criteria
- SC-001 12个并发领取同任务仅1成功。
- SC-002 过期接管后旧代次四种写操作均无状态变化，旧产物无法覆盖新文件。
- SC-003 独立双实例真实执行、强杀接管、全量容器和最终远端CI通过。
## Assumptions
共享MySQL和素材卷；每实例仍一个worker，默认租约15秒并周期续期，不承诺按实例数量线性加速。无Redis/MQ/跨地域文件复制。
