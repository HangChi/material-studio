# Feature Specification: 个人历史与多任务跟踪

**Feature Branch**: `005-history-tracking`

**Created**: 2026-10-29

**Status**: Ready for implementation（2026-10-29细化）

**Input**: 按项目迭代图从001总体基线拆分，独立完成SDD与TDD周期；不使用子智能体。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 恢复本人历史与结果 (Priority: P1)

用户刷新后恢复时间、状态、结果/原因，并继续跟踪未结束任务。

**Why this priority**: 本feature的主要用户价值。

**Independent Test**: 本人历史分页、空态、失败恢复、结果预览；两个身份相互隔离。

**Acceptance Scenarios**:

1. **Given** 本人有超过一页记录且含未结束任务，**When** 刷新历史页并加载更多，**Then** 时间倒序无重复，未结束任务自动更新，成功图片可预览。
2. **Given** 分页暂时失败或切换访客，**When** 重试/切换完成，**Then** 分页失败保留原卡片和游标，新身份不显示旧记录。

### User Story 2 - 可靠管理多任务查询 (Priority: P2)

用户连续创建任务，查询异常时恢复查询且不会被误报制作失败。

**Why this priority**: 补齐该切片可独立使用的可靠性。

**Independent Test**: 三任务乱序不串扰；查询失败只影响请求；终态/卸载/换身份清理，迟到响应无效。

**Acceptance Scenarios**:

1. **Given** 三项任务不同状态，**When** 查询乱序返回且一项503，**Then** 各自更新，503仅暂停该项并提供恢复，不能改为制作失败。
2. **Given** 任务终结、页面离开或切换身份，**When** 旧请求返回或两个查询周期经过，**Then** 旧结果无效且不再为已清理任务自动查询。

### Edge Cases

- 同时间分页、新记录插入、无记录、旧页活动任务、401/404/503、重复加载更多、旧版本与无效响应均须验证。
- 后续feature未实现的能力不展示为可用入口；不以占位数据声称完整闭环。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须从服务端读取本人历史、创建时间、阶段、结果和失败原因，刷新不丢失。
- **FR-002**: 系统必须按身份/任务分别更新，多个任务状态、错误、结果互不影响。
- **FR-003**: 系统必须查询异常与制作失败独立，保留旧快照并提供恢复途径。
- **FR-004**: 系统必须自动跟踪未结束任务，终态停止；无待办、页面离开、用户切换清理定时器和请求。
- **FR-005**: 系统必须忽略旧身份、旧请求及旧版本响应，不使终态回退。
- **FR-006**: 系统必须完成全题容器验收、CI关键测试与完整交付README，说明投入、来源、AI流程及部署回滚。

### Key Entities

- **身份**：个人资源归属。
- **素材/任务**：由前置feature提供或本期引入，字段约束沿用总体模型并在本feature计划细化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三任务不同状态及乱序更新全部归属正确，查询503后可恢复且无虚假FAILED。
- **SC-002**: 刷新恢复所有本人记录；另一个身份不可见，旧身份响应无法覆盖。
- **SC-003**: 终态、离开或切换后观察两个轮询周期无多余自动请求。
- **SC-004**: 原题R-01～R-14逐项标注实现与运行验证，按源码验收commit交付。

## Assumptions

- 依赖003和004；最终验收不能只依赖夹具或组件测试。
- TDD必须记录真实RED/GREEN；计划中的测试不代表已运行。
