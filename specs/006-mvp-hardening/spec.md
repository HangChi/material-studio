# Feature Specification: MVP验收收尾

**Feature Branch**: `006-mvp-hardening`
**Created**: 2026-10-29
**Status**: Ready for planning
**Input**: 修复历史刷新游标遗漏，补结果图片加载失败提示/重试，完成10次受理小于2秒的实测；SDD+TDD，禁止子智能体。

## User Scenarios & Testing

### US1 - 刷新不遗漏记录 (P1)

历史已读到末页或旧分页位置时，新记录超过一页，刷新后仍能加载所有中间记录。

1. Given 原历史到末页，When 新增超过一页后刷新，Then 使用最新首页的分页位置显示加载更多，保留已展示记录并去重。
2. Given 已有旧游标，When 刷新成功后继续加载，Then 不跨过新旧首页之间的记录。
3. Given 刷新失败，When 重试，Then 既有记录与原游标保留，不能丢失更高版本或终态。

### US2 - 结果图片错误可恢复 (P1)

制作成功但结果图片暂时读取失败时，用户能看到资源错误并单独重新加载图片。

1. Given 成功任务，When 图片加载失败，Then 提示图片错误，任务仍显示成功，不进入任务轮询或重新提交制作。
2. Given 图片加载错误，When 点击重新加载，Then 发起新的私有图片读取，成功后恢复预览，失败可再次重试。
3. Given 多个结果，When 一张失败或重试，Then 其他图片、身份与任务状态不受影响；换身份/页面离开不保留旧预览状态。

### US3 - 受理时延验收 (P1)

演示任务制作总耗时至少6秒时，正常本地负载下连续10次受理均能在2秒内显示新任务编号。

1. Given 应用与数据库健康，When 准备好图片后逐次提交10项任务，Then 每项记录受理耗时和新任务编号，不将6秒后台制作计入受理耗时。
2. Given 实测结果，When 汇总，Then 保留逐项数据、测量方法、负载与边界，明确API计时和浏览器可见性观察的区别。

## Functional Requirements

- FR-001：成功刷新将分页链重新定位到最新首页；失败保留旧链，历史按ID合并且不回退版本。
- FR-002：结果图片错误单独提示并可重复重试，不修改成功状态或其他任务。
- FR-003：图片重试仍使用本人受保护地址，不使用公共文件绕过身份，也不调用制作POST。
- FR-004：实测10次受理、每项后台总耗时至少6000ms，每项受理目标小于2000ms；不删掉超标样本或伪造浏览器数据。
- FR-005：更新总体基线的缺口、验收记录和运行说明，保留远端CI/TLS等未验证边界。

## Success Criteria

- SC-001：新增记录跨页和原末页两种刷新路径均无遗漏/重复；刷新失败仍可从原位置继续。
- SC-002：两项成功结果中一项失败/恢复，另一项不受影响；制作状态一直保持成功。
- SC-003：10项实测全部记录并逐项检查2秒目标，制作时间不低于6秒；目标未满足时如实记录并处理。

## Assumptions

承接001总体目标及005代码；不新增业务接口或数据库结构，不扩展重启续跑、自动重试和账号体系。
